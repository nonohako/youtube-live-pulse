# Live Pulse 24시간 통계 수집

Fly.io의 Node.js 서버 한 대가 1분마다 공식 YouTube Data API에서 구독자 수와 채널당 최근 일반 영상·쇼츠 최대 8개의 조회수를 수집합니다. 업로드 목록은 5분마다 갱신합니다. 현재 라이브·예약 콘텐츠는 제외합니다. PC를 꺼도 서버 수집은 계속되지만 PC 알림은 기존 앱이 실행 중일 때 동작합니다.

## 저장과 비용

- Upstash Redis에 최근 30일의 분 단위 기록을 저장합니다. 공개 API 통계의 보관 제한에 맞춰 서버와 앱의 클라우드 캐시 모두 만료시킵니다.
- 미수집 기간의 값을 추정하거나 보간하지 않습니다. 수집 시점부터 기록이 생깁니다.
- 기존 로컬 기록·가져온 구독자 기록은 업로드하거나 덮어쓰지 않습니다. 클라우드 기록을 표시할 때만 합칩니다.
- 서버는 1분 기록을 보존합니다. 앱 영상 차트 캐시는 영상별 최대 2,000개로 압축하며 처음과 마지막을 보존합니다. 구독자 기록은 30일의 실제 분 단위 샘플을 모두 유지해 일별 마감값이 변하지 않도록 합니다.
- 현재 채널 2개는 기본적으로 하루 약 3,456 YouTube 쿼터 단위가 필요합니다. 최초 실행·실패·재시작에 따른 추가 요청은 별도입니다.
- 정상 수집 시 Redis는 분당 6개 명령, 앱 한 대가 계속 동기화하면 분당 약 2개 읽기 명령을 사용합니다. 30일 합계 약 345,600개로 500,000개 무료 한도 안입니다. 긴 공백의 최초 동기화는 추가 요청이 발생합니다.
- Fly는 512MB shared CPU 한 대만 유지합니다. 수집 서버는 자동 정지하지 않습니다. 두 대로 늘리면 비용과 중복 API 호출도 늘어나므로 `--ha=false`를 사용합니다.

## 배포

1. `fly auth login` 후 개인 조직에서 앱을 생성합니다.
2. `cloud/fly.toml`에 실제 `app` 이름을 설정합니다. `CHANNEL_IDS`에 수집할 채널 ID를 쉼표로 구분해 넣습니다(최대 5개).
3. 다음 값은 **Fly secrets**로 등록합니다. Git·Docker 이미지·공개 설치 파일에 넣지 않습니다.
   - `YOUTUBE_API_KEY`: YouTube Data API v3가 활성화된 키
   - `UPSTASH_REDIS_REST_URL`: 기존 DB HTTPS 주소
   - `UPSTASH_REDIS_REST_TOKEN`: 해당 DB 쓰기 토큰
   - `CLOUD_READ_TOKEN`: 무작위 32바이트 이상으로 만든 별도 앱 연결 키
4. `cloud` 폴더에서 `fly deploy --ha=false`를 실행합니다.
5. `/healthz`는 프로세스 점검입니다. 인증된 `/v1/sync` 응답의 `status.lastSuccessAt`과 서로 1분 떨어진 실제 저장 기록으로 수집 성공을 확인합니다. 인증 없는 `/v1/sync`는 401이어야 합니다.
6. PC 앱 설정의 **연결 파일 가져오기**에서 `{ "cloudUrl": "https://앱이름.fly.dev", "cloudToken": "CLOUD_READ_TOKEN 값" }` 형식의 개인 JSON 파일을 선택하거나, 주소와 연결 키를 직접 입력합니다. 주소를 비우고 저장하면 연결을 해제합니다. 서버의 YouTube 키와 Redis 쓰기 토큰은 PC에 배포하지 않습니다.

클라우드 조회 키는 앱의 기존 개인 설정 파일에 저장되며 renderer 상태 응답에서는 숨깁니다. 공용 릴리스에는 사용자별 주소와 키가 포함되지 않습니다. 서버 채널 목록은 앱 채널 추가와 자동 연동되지 않으므로 새 수집 채널은 Fly 설정에도 추가해야 합니다.

## 장애와 복구

- 외부 요청 제한 시간과 중복 실행 방지로 느린 요청의 무한 누적을 막습니다.
- 실패 시 이전 기록을 보존하고 다음 주기에 재시도합니다. 정상 값처럼 0을 저장하지 않습니다.
- 앱은 마지막 저장 커서 다음부터 다시 읽습니다. 한 번에 최대 10페이지(2,400분)를 읽고 남은 공백은 다음 동기화에서 이어갑니다.
- Upstash 키는 `live-pulse:v1:*`에만 기록합니다. 다른 앱의 데이터에는 접근하지 않습니다.
- Fly health check 성공만으로 YouTube 수집 성공이라 판단하지 마세요. 앱 설정의 동기화 상태와 Fly 로그의 수집 시각·오류를 함께 확인합니다.
- API 키 제한은 YouTube Data API만 허용하는 방식이 적합합니다. 웹사이트 referrer 전용 키는 서버 요청에서 거부될 수 있습니다.

검증: `node --test test/cloud.test.js`, 전체 `npm test`, 패키지 `--smoke-settings`.

명령줄 온보딩도 지원합니다: `라이브 펄스.exe --cloud-config "연결 JSON의 절대 경로"`. 실행 중인 앱에도 연결 설정만 전달하며 관련 없는 설정과 기록은 보존합니다. 연결 파일에는 서버용 API 키나 Redis 쓰기 토큰을 넣지 않습니다.
